# Brief — ruling on question 4, the prompt record (2026-09-25)

Saved before execution, as the standing contract requires. The operator's text
is unedited.

---

Ruling on question 4, 2026-09-25: the prompt-record rule binds from the release that ships it, and the gap before it is labelled, not exempted.
- Every reasoning row written before the release (including ids 2358–2441 and any written before item 4 ships) gets a prompt record rebuilt from its stored inputs through the prompt code as it stood at that row's run time, stored append-only with kind = "reconstructed", the code version used, and the reconstruction date. It is never presented as the prompt sent.
- From the release onward, every reasoning row must carry kind = "sent", the exact prompt or its hash plus full inputs, written in the same transaction as the row. The gate fails by name on any post-release row without it, and on any row of any date with no record at all. Plantings for both.
- The page and the Record page show reconstructed rows' prompts labelled "reconstructed" in those words.
- Order: let the running 5a workflow finish and release; item 4 goes immediately after it, ahead of the live migration and 5b, because each day of delay adds reconstructed rows.

---

## How this brief is read

**"The release that ships it" is an instant the record itself holds.** The
first `db.init` under the new schema writes it once into `meta`; the trigger and
the gate read it from there. No literal is guessed ahead of a release whose
minute nobody knows, and no row falls between two definitions.

**"Every reasoning row written before the release" means all of them, the
historic ones included**, not only those after the 24 September ruling: the gate
fails "on any row of any date with no record at all", so every row needs one.

**"As it stood at that row's run time"** is the code the scheduler was running
when the row was written: the main checkout's commit at that minute, read from
its reflog. Until 23 September the scheduler also ran uncommitted edits in the
main checkout, which no commit holds. Where the commit may not be the code that
ran, the record says so in words rather than claiming more than it knows.

**Order**: 5a gate and release, then item 4 (build, gate, release, then the
reconstruction written to the live record), then the live migration and 5b.
