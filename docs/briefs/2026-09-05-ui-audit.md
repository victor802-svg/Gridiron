GRIDIRON_UI_AUDIT — drive the interface like a person, fix what breaks

One session, RUN TO COMPLETION — NO STOPPING. The operator reports UI
bugs without naming them: find them by USING the app, not by reading
it. All laws bind; MENTOR.md first; briefs process; /closeout, verdict
slots empty. Verify this paste ends with "=== END OF PASTE ===".

THE NO-STOP CONTRACT: never stop to ask; forks resolve by law, then
precedent (MENTOR §4), then the conservative default, each recorded
under "Rulings taken in your absence"; a finding needing an operator
decision is written down as a DECISION and the session CONTINUES;
retry a failed tool once, then work around and record; commit and push
at every phase boundary and after each fix, verified with git log
origin/master; if context runs short, finish the phase, write the
report with a NOT REACHED list, close out, push. Done means the push is
verified, not the last file saved.

WHY THIS SESSION EXISTS: every UI defect this project has found was
found by LOOKING or by DRIVING — the black-on-black token collision,
the bar whose contents escaped it, the tabs off-screen behind an
invisible scrollbar, the tooltip caveat no phone could show, the live
tick that threw on every poll, the panel that was hidden to every
assertion and visible to every click. The suite is green today and the
operator still sees bugs. Assume there are several and that none of
them will fail a test.

PHASE U1 — DRIVE IT (find, do not fix)
Real browser, real record, both widths (1440 and 390), and both kinds
of state: a sport with a full slate and a sport with none. For every
route (Picks, Record, Results, Settings, login) and every control,
perform the action a person would and record what happens:
- Click every control twice — sort, tier, market tabs, the view menu
  and both its toggles, hero arrows and dots, card expand and
  collapse, calendar day select and clear, every Settings toggle and
  time field, sign-out. Then switch sport and do it all again. Then
  switch sport MID-transition and mid-load.
- After every click: console errors, network 4xx/5xx, whether the
  thing that should have changed changed, and whether anything ELSE
  moved (scroll position, selection, filter, tab).
- Rapid interaction: double-click a tab; click two tabs within 100ms;
  click a card while the grid is fading; switch sport while the hero
  is sliding; press Escape and Tab through everything.
- Deep-link and reload: open every route by URL directly, reload on
  each, use browser back and forward across sport and tab changes.
- Empty and edge states: a sport with zero picks; a tab with zero
  picks; a fully settled slate; a card with no line; a retired market;
  a tier with no cards; the offline banner.
- Measure, do not eyeball: element boxes for overlap and clipping;
  hit-testability of everything clickable (a control covered by the
  sticky header or a display-overridden panel is broken even if
  visible); horizontal overflow; tap targets at 390; contrast on every
  route; and whether any element with [hidden] is still hit-testable.
- Read the rendered text of every route through the plain-words scan
  INCLUDING the LLM forecaster view and the early view.
Output docs/UI_FINDINGS-<date>.md: every finding with route, width,
exact steps to reproduce, what happened, what should have happened, and
a severity (BROKEN > MISLEADING > AWKWARD > COSMETIC).

PHASE U2 — WHY DIDN'T A TEST CATCH IT
For each U1 finding, name the reason no test failed. Expect these
classes and say which applies: the fixture world cannot contain the
shape (the use_llm=False class); the assertion checks a proxy rather
than the thing (class toggled, not opacity actually partial; attribute
set, not element unclickable); the test drives the app differently than
a person (no rapid clicks, no reload, no back button, waits a person
does not perform); the surface is only reachable by hover; the state
never occurs in the test record.
Then fix the CLASS for at least the three worst: extend the fixture,
assert the thing rather than the proxy, or add the interaction the
tests never perform.

PHASE U3 — FIX
Fix every BROKEN and MISLEADING finding, one commit each, each with a
planting where a class is involved, and each verified by re-driving the
exact steps from U1. AWKWARD and COSMETIC findings are fixed only if
the fix is small and obvious; otherwise they go in the report as
DECISIONS. No redesign, no new features, no tuning — this session makes
what exists work.

PHASE U4 — PROVE AND REPORT
1. Re-drive the full U1 script end to end and show every finding gone;
   any that remain are listed as such.
2. Full suite under .venv, no skips; every planting; verify.py green.
3. docs/UI_FINDINGS-<date>.md completed with, for each finding: the fix
   commit, the test that now covers it, and the class fix if one was
   made.
4. A one-paragraph verdict in plain words at the top: can a person use
   this app today without hitting something broken, and what is the
   single thing the operator should look at first.
5. /closeout, verdict slots empty, push.
