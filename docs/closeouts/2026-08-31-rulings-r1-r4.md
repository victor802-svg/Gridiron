## 2. Deviations from the rulings, stated up front

1. **Ruling 3 asks for "the two most consequential changes"; today the
   record cannot say which those are.** The only measure of a factor's
   consequence here is its effect on the record, and every sport is at
   2–25 settled predictions per factor. Sorting by an effect computed on
   two is noise with a sort applied, and the sentence coming out of it
   would tell a reader those two mattered most.
   So the ranking is **gated**: `_rank_changes` sorts by |effect| only
   when every candidate clears `RANK_MIN_SETTLED` (= `TIER_MIN_SETTLED`,
   reused rather than invented), and reports which ordering it used. With
   the gate cleared the line may say "the two that moved the answer most"
   and call the rest "smaller changes"; without it the two named are the
   first two **declared** and the line says "and 17 more", claiming
   nothing about size. **Every set falls back today.** The wording switch
   is an honesty switch, not a formatting option.
2. **Ruling 1's fix for `pickSentence` was deletion, not repair.** It had
   zero callers. Rewriting it to comply would have shipped a server
   function nobody called feeding a renderer nobody called.
3. **Ruling 4 logs MLB only.** `declared_rungs` returns `()` for any sport
   without a declared ladder rather than inventing one to have something
   to record. MLB is the only sport with a ladder, which is why the ruling
   is about MLB.

## 5. Vacuous passes found, and the class fix for each

1. **A dead K1 defect kept in reserve.** `pickSentence`'s else branch chose
   a verb by market type — the exact shape that put "97% chance WAS covers"
   on 34 cards. It could not fire, because the function had no callers, so
   no test could ever have caught it and none did. *Class fix:* ruling 1's
   JS scan reads the file rather than the behaviour, so an unreachable
   violation is still a violation. It was the first thing the scan found.
2. **Two factors sharing one plain name.** `mlb_park_factor` and
   `mlb_prop_park_factor` both said "how much scoring this park allows" —
   the same measurement asked of two different questions. Each is right in
   its own sentence and no pick card was ever wrong, so nothing failed. It
   is visible only where names are listed without their market, which is
   what ruling 3's new list does. Found one render after building it.
   *Class fix:* a test forbids two factors in a sport sharing a plain name.
   Across sports stays legal — NFL's `home_field` and NBA's
   `nba_home_court` live in records LAW 6 keeps apart.
3. **LAW 6's tripwire was unreachable from the prediction path.**
   `require_sport` lived in `calibration`, which names market columns, so
   LAW 1 rejects any prediction-path module that imports it. A module on
   that path needing LAW 6's check is the normal case, not an odd one.
   *Class fix:* both it and `CrossSportAggregation` moved to `config`
   beside `SPORTS`; `calibration` re-exports them, so no caller changed.
   This is the second time this session a helper had to be moved out from
   behind a market-naming module (`strip_market_suffix` was the first).
