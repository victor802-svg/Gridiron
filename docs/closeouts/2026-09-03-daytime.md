`weather_observed` exists and the capture pass writes **nothing** into it, on
purpose. `weather_forecasts` is what was expected; the new table is where an
observation goes *when a source for one exists*, and this project has none
wired. Copying a forecast into an observations table is exactly the confusion
the two tables prevent.

**So the recorded defect is not yet repaired** — the college wind coefficient is
still fitted on observed weather and applied to forecasts. What changed is that
the two can now be stored apart, which is the precondition.
