## 2. What was deleted

The desk (a scrolling frame of tiles beside a 440px rail, above 1280px) and the
compact rows below it. **Markup, CSS, the breakpoint machinery and the tests**,
with **zero allowlist additions**.

`DESK_MIN_WIDTH`, `DESK_QUERY`, `isDesk`, `applyDeskClass`, `selectTile`,
`paintRail`, `paintGlance`, `pickTile`, `pickRow`, `applyTileState`,
`tileNumber`, `paintTileCorner`, `deskKeys` and the media-query re-render are
gone. So is the long comment explaining how the JS and the CSS came to disagree
about which layout was live — **that whole class of failure goes with the
second layout**, because crossing a width no longer changes which elements
exist.

`tests/test_desk.py` (36 tests) is deleted and `tests/test_cards.py` (28)
replaces it. Half the old file existed to prove the two layouts agreed with
each other, or that the breakpoint switched at the right moment. **Those tests
are not weakened, they are answered**: a claim about whether two layouts agree
cannot be made about one.

## 4. The guards, re-pointed

| guard | was | is |
|---|---|---|
| no truncation | the frame at desk width | **every element in the slate, at 390px** — where the truncation actually was |
| selection leaves the frame alone | `selectTile` saving and restoring scroll | the card's toggle may not re-render the slate |
| dead selector | `tile.querySelector('.tile-score')` | `node.querySelector('.card-when')` in `applyCardState` |
| tap targets, overflow, one greeting, no re-sort, live mark never green | the desk | the cards |

**The truncation guard is now stronger than the one it replaces.** The old test
looked at desk width, where nothing truncated, and missed "BRISSETT · PASSI…"
on the phone for weeks.

## 5. What the plantings caught

Three new, 160/160 overall:

- **a market tab row written into the renderer** — caught two ways: scanning
  the renderer for written-out market labels, and asserting every sport's real
  tabs equal `config.SPORT_MARKETS`. That second check is the only way to tell
  a derived row from a hardcoded one that happens to be right today.
- **a card showing two numbers collapsed** — the market hint is in the markup
  by design (the brief asks for a hover reveal); what keeps the card honest at
  rest is that it starts at zero opacity, and the plant removes that.
- **two sentences naming opposite sides** — §11.

## 6. The hero

Sharpest disagreement by default, most confident when the sort says so, five
dots and two arrows. The dots were rendering as **8×44 bars**: the page-wide
44px minimum tap target stretched them. Shrinking the target would have been
choosing the look over the reader, so **the button is 44px and draws an 8px
mark inside it** — and the test's exemption for them was removed, because there
was nothing left to exempt.

**Its tag agreed with nobody.** It read "Sharpest disagreement tonight" on a
slate ten days away, because the brief's wording assumes tonight — the brief
was written about tonight. The tag now agrees with the heading about what today
is rather than deciding again.

## 7. What was deliberately NOT built

**A second sub-line.** The brief asks for "13 strong picks · first pitch in 2h
14m · 15 more didn't clear the bar". All three facts were already composed and
already on the page: `glance.count_lines` carries the tier-aware count, the
ticking clock carries the countdown, `below_floor` carries the shortfall.

`slate_subline` was written, then deleted rather than shipped. It would have
been a second sentence saying what the first already says — and worse, **the
server cannot know which tier the reader is filtered to**, so its count would
have been the wrong one whenever the filter was on. Two claims about one thing,
one of them wrong, is not more information.

## 8. The palette, and the one place it was not followed

Applied as specified: bg `#0F1114`, card `#171A1F`, raised `#1D2127`, hairline
`#262B33`, text `#F4F5F7`, muted `#9AA3AF`, `--win #22D37A`, `--loss #FF6B6B`.
Radii 22/28/999. Motion vocabulary unchanged — five transitions moved from
`background` to `background-color`, which is what the vocabulary permits and
what avoids a layout on every frame.

### 8.1 `--faint: #5F6975` fails WCAG AA, measured

**3.17:1 on a card**, against the 4.5 minimum, by this project's own
`tools/contrast.py`. That token draws **every sample size**, and there is a
dated ruling here that an N nobody can read is an N that is not there — LAW 4
means legible, not merely present.

So `#5F6975` is used as `--faintest`, which draws no sample sizes, and `--faint`
is a lighter tone from the same family. **Every pair now passes; the worst is
5.54:1.** This is a deviation from the brief and it is recorded as one.

### 8.2 Manrope is not self-hosted, and cannot be

There is **no font binary in this repository**, and adding one would mean
shipping a file nobody can diff. Linking a CDN would put a network dependency
in a local-first app that a test already forbids. Manrope and Inter are named
first, so a reader who has either installed gets it, and the stack falls back to
the system face.

**No condensed and no monospace anywhere**, achieved by pointing `--cond` and
`--mono` at the same stack — one edit reaching all forty rules that used them,
including the ones nobody would have remembered. Tabular figures survive on
`font-variant-numeric`, which is what that property is for. A test asserts no
monospace or condensed face is in use anywhere in the slate.

## 11. Three defects this work exposed, none of them cosmetic

**One. 68 of 321 live cards named opposite sides.** A card read *"Miami covers
+7.5"* beside *"chance Miami does not cover"* — the percentage attached to the
wrong claim. `side_named` flips the name when the model takes the NO side;
`chance_clause` then negated the verb as well. A double flip.

It survived every guard: "one door for the side" passed because both functions
asked `side_named` and got the same **name**; "the side, in prose, anywhere"
passed because both sentences were grammatical and each was plausible alone.
The two fixes that combined to cause it were each right on their own and
arrived sessions apart. **The new planting does not check either sentence — it
checks that the two agree**, which is the only thing neither could be asked
alone.

**Found by rendering.** The old tile put those two strings at opposite corners;
the hero puts them four lines apart in large type.

The first fix was itself half right, and the old tests said so: `flipped_line`
negated the number without the opponent gate `side_named` applies to the name.
Every live card carries an opponent, so the two never disagreed in production —
**they disagreed on exactly the inputs a test writes by hand**, which is the
worst place for a rule to differ. `side_flips` and `spread_verb` are now the
one door each.

**Two. A dangling brace silenced half the stylesheet.** Deleting the desk left
its `@media (min-width: 1280px) {` opener behind, so the tier filter, the slate
clock, the live mark and the sport tabs' collapse behaviour were all nested
inside a query that only matched above 1280px. The CSS still parsed. Every rule
still existed. They simply stopped applying at the widths that needed them
most, and the header ran 73px off the edge at 390px.

**Three. A test that passed by accident.** `_open_week` was satisfied by the
render from an earlier, un-intercepted fetch — a test that routes `/api/week`
was asserting against data it had not stubbed. The old helper hid this because
changing the viewport crossed the breakpoint, which forced a re-render that
happened to be the routed one. One layout has no breakpoint to cross.
