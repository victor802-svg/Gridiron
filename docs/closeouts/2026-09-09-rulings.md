**The venue answers about sixteen days out.** The project was asking two hours

### What was built

* **`venue_quotes.read_kind`** -- `'open'` or `'near_start'`, defaulting to
  `'near_start'`, which is what every existing row actually is. Migrated by
  `at_the_line.ensure_read_kind` with a plain ADD COLUMN.
* **`tasks._opening_read`** on the four-hourly refresh: every scheduled game
  outside the near-start window whose newest opening read is more than
  `OPENING_READ_HOURS = 12` old. First live run: **201 predictions due, 782
  quote rows written** across NFL, college football and basketball -- the
  Seahawks game alone got 46.
* **The near-start read is untouched.** It is still the only look a claim, an
  at-the-line row or a CLV pair may cite. `at_the_line._looks` filters to it,
  and `audit.check_claims_price_at_the_line` -- the name the brief gave it --
  reads the RECORD and fails on any claim whose quote is an opening read.
  Planted: a claim priced off an open read a week before kickoff is caught by
  name. Verified after the live run: 308 claims in the record, none of them.
* **`drift.venue_pairs` / `venue_report`** -- the venue's own open-to-close
  pair, gated at the same fifty and never averaged with the media pairs. Zero
  pairs today, and it says so: the 308 existing claims are on games that had
  no opening read when they were written. Pairs accrue from tonight.
* **The card**: `PAYS 2.02x / read 8:27 PM - re-read near kickoff`. The words
  are the server's and the instant is turned into the reader's clock by the
  renderer, as the kickoff line has always worked.

### The falsehood the first render caught

The operator's wording was "venue has not listed this yet". Rendered, the
first Seahawks card said exactly that -- about a **receptions prop**, while
`KXNFLREC-26SEP09NESEA` was open with seventy-one contracts on it. The venue
had listed it; this project does not read prop prices at all.

So the chip tells **three silences** apart (`language.no_price_words`):

* the venue was asked and has nothing -> "venue has not listed this yet";
* nobody asked, because the market is a prop and there is no crosswalk ->
  "not read at the venue yet";
* the near-start read has not happened, which the day strip says once at the
  top of the page instead of forty times down it.

A card that says the venue has nothing must be about a market the venue was
asked. That was worth catching before it shipped, and only rendering caught it.

## Ruling 3 — the two readings, and whose they were

**Reading A**: `--win` and `--loss` are the verdict of a PICK. A club's game
is not a pick, the stylesheet named the edge line as their only home, and a
form streak is therefore outside the law -- colour it some other way.

**Reading B**: the rule exists to stop a colour reaching for importance it has
not earned -- green as the interactive accent, red as every warning. A game a
club won is the most literal thing either colour can mean, so this is the
colour doing its one job.

**The operator chose B, on 2026-09-09.** The stylesheet now says so, with the
date of the ratification rather than the date of the request, and records that
both readings were put to him.

**And the standing rule that matters more**, now in CLAUDE.md: when a law's
own words must be stretched, reinterpreted or amended for the work to proceed,
that is the operator's call and the work waits. Yesterday the session read the
law itself, decided, built, and amended the text to match. The reading was
sound. It was not the session's to make, and one that went the other way would
have shipped just as quietly.

## Ruling 4 — one line, and the proof

`audit.check_the_browser_files_parse` runs `node --check` on `app.js` and
`sw.js`, **first** in the gate's static list, because a file that does not
parse makes every scan after it meaningless. Node comes from Playwright's own
driver, which is already a dependency, so the gate does not depend on whatever
is installed on the machine -- and if neither that nor PATH has one, it RAISES
rather than passing, because a check that cannot run is not a check that
passed.

HTML and CSS are not parsed and the code says so rather than implying
otherwise.

**The planting** rebuilds the 2026-09-08 defect character for character -- an
expand button called `more`, a link called `more`, same block -- in a COPY of
the shipped files.

**And the gate itself was proved**, by breaking the real `app.js` for one run:
