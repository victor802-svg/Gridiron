## 2. Ruling 2 — the flagged method

**`config.FLAGGED_METHODS` declares which markets carry a finding.
`language.METHOD_NOTES` holds the words.** Split for the reason every
plain-words split exists: nothing a reader sees is composed outside
`language.py`.

**Four sports are flagged** — nfl, mlb, nba, cfb — because all four declare a
`total` and all four ask it at the ladder rung nearest their own expectation.

**DERIVED, NOT WRITTEN.** The map is built from `SPORT_MARKETS`, so a sixth
sport declaring a total is flagged the day it is declared. STEP 4 found a
declaration disagreeing with a hardcoded copy of itself **four times in one
session**, every one silent, and a fifth copy is not written here.

**UFC's `rounds` is a total and is not flagged**, and the scan reads why from
the code rather than from a list: `questions.ufc_rounds_rung` takes the bout's
**scheduled length** — 2.5 for a three-rounder, 4.5 for a five — while every
self-chosen rung is `questions.<sport>_<market>_asked` and takes the model's
own expectation. The naming carries the distinction and the guard asserts it,
so a future `_asked` for an unflagged market is a gate failure.

### The two rulings taken in your absence

**One. The note is on the collapsed card face, not one tap in.** A caveat
behind a tap is a caveat most readers never reach, and the reader taking the
percentage at face value is exactly the one it is written for. It does not
break the cards brief's R2: "one number, and the word for what it is a number
of" is a rule about *numbers* on the collapsed face, and this is a sentence
that asserts no probability of its own.

**Two. Every card flagged means NO HERO**, rather than a hero with a caveat
attached. "Never" is the ruling's word. On the totals tab every card is
flagged; the hero hides and the grid opens at rank 1 showing all of them.

### The bug the second ruling nearly shipped

`const rest = open.slice(1)` was correct for as long as the hero always took
`open[0]`. **The moment the hero can refuse the top card, slicing position 0
deletes that card from the page** — shown by neither the hero nor the grid.
On the totals tab that is *every card on the slate*: the page would render
empty while reporting a full one, which is a worse failure than the one the
ruling was fixing.

The grid now drops the card the hero actually leads with, **by identity**.
`plant_a_flagged_market_leading_the_page` breaks both halves and requires both
to be caught.

## 3. Ruling 4 — the fonts

**Vendored:** `manrope-latin.woff2` (24,836 B) and `manrope-latin-ext.woff2`
(15,120 B), Manrope v20 variable, weight axis 200–800, with `OFL.txt` and
`SOURCE.md` beside them.

**The instinct is answered, not waived.** "A binary nobody can diff is a thing
nobody can check" is why the app icon is drawn in code. The ruling drew the
line correctly — a font carries outlines, not behaviour — but the instinct
still has to be met, so `SOURCE.md` records each file's origin URL, byte size
and SHA-256, and **`audit.check_vendored_fonts` re-hashes the files against
that table in the gate.**

**The table is the one declaration.** The hashes are not repeated in Python;
the guard parses the markdown. A second copy would have been the fifth
declaration-versus-hardcoded-list drift of the week.

**The quiet fault is the fourth one.** A swapped file fails a hash. A file that
was *never recorded* fails nothing and looks like it belongs — so the guard
also fails on any binary in `web/fonts` the table does not name.
`plant_a_binary_with_no_provenance` is that one.

**Three decisions, each recorded where it was made:**

- **Two subsets, not six.** 40KB rather than 100KB. Everything this interface
  renders is English composed in `language.py`; team and fighter names are
  stored transliterated. A glyph outside the ranges falls through the stack,
  which is what a fallback stack is for.
- **The variable font, not static instances.** The stylesheet asks for weight
  **640** in two places. No static instance can answer that — it would round to
  600 or 700 in silence, invisible in review and visible on the page.
- **`.gitattributes` now exists** and declares `*.woff2 binary`. `core.autocrlf`
  is true here and this repository had no `.gitattributes` at all. Git's
  heuristic would almost certainly spare a font; **"almost certainly" is the
  wrong standard for a file whose hash the gate enforces.** Verified: the
  staged blob is byte-identical to the file on disk.

**The offline shell caches them.** A worker that caches the stylesheet asking
for a font and not the font renders the offline app in a fallback face — the
one condition where the difference is most visible and least expected.
`SHELL_CACHE` bumped to `v3`.

**The Content-Type was wrong and nothing would have noticed.**
`mimetypes.guess_type("a.woff2")` returns `(None, None)` on a stock CPython, so
`StaticFiles` was serving a vendored font as an octet-stream. Browsers sniff
the `wOF2` magic and render it anyway — **which is exactly why this would
never have surfaced.** `font/woff2` is the registered type (RFC 8081) and is
now registered at import.

### The guard fired within minutes, on me

`git stash` round-tripped `OFL.txt` through `core.autocrlf`, added **93 bytes**
of carriage returns, and `check_vendored_fonts` failed exactly as it was built
to — naming the file, the byte count and both hashes.

**`.gitattributes` had been drawn one file too narrow.** `*.woff2 binary` and
nothing about the licence, which is also in the hash table. Now
`gridiron/web/fonts/OFL.txt -text`, verified by stashing and popping and
re-hashing: 4,384 bytes both sides.

**A licence's bytes are the licence** — a document received under terms,
recorded by hash and shipped unchanged. Line-ending normalisation is a
modification, small and silent, and it is the kind that makes a provenance
table look like it is lying about the file rather than the file lying about
the table. Pinned by `test_the_licence_is_byte_stable_across_a_checkout`.

**This is the argument for the guard, made by the guard, on its first day.**
Had the table been decoration, the licence in this repository would now differ
from the licence that was published and nobody would ever have known.

## 4. What was found on the way — three red tests, none of them mine

**Not in the brief.** Three tests were already failing at `HEAD`, verified by
stashing every change and running them again. All three trace to one event: the
**first live `predict:nfl` run of the moneyline declared the night before**,
which wrote 16 rows at 2026-09-04T18:40Z. Three numbers that had been quietly
true stopped being true, and the overnight close-out's "966 tests, 0 failures"
was accurate when it was written and was no longer accurate hours later.

**That is worth saying plainly: this project's suite reads the live record, so
a green gate has a shelf life.** Nothing was wrong with the run that wrote
those rows. It is what a new market doing its job looks like.

| test | what it was | verdict |
|---|---|---|
| `test_superseded_forecasts_are_not_in_the_arithmetic` | **a real defect** | fixed, §4.1 |
| `test_a_factor_set_query_still_returns_its_own_rows` | a remembered count | rewritten to read the record |
| `test_the_generated_why_agrees_on_every_prediction_in_the_record` | a checker blind to one shape | pointed at the composer's own door, §4.2 |

### 4.1 The superseded count reported less than it was hiding

`views.week` held **two different definitions of "the same question"**:

- the **fetch** drops a row that a later row of the **same factor set**
  replaced — the door `_superseded_ids` and `calibration` both use;
- the **Python dedup** then drops what is left over a **broader** key, which is
  what catches the 2026-08-29 double run *across* factor set versions.

Both kinds of hiding are real. The reported figure was the difference between
the two definitions, so it only ever counted the second.

**On the live NFL slate it reported 29 while hiding 45.** The payload comment
calls this figure "how the operator finds out a prediction task ran twice",
so a count that is quietly short is the one thing it must not be.

**Counted, not subtracted.** One query over the slate, minus what the page
shows. There is no second definition left to drift from.

### 4.2 A checker that could not see the sentence it was checking

`why_sentences` does not render an asked-distance factor's declared WHY phrase.
It replaces it with the **measured distance woven in** — "the question sits 1
point above what the model expects" — which says how far and which way where
the declared phrase says only that a distance exists. That specialisation has
existed since 2026-09-03 and `language.asked_distance_phrase` is its one door.

**The checker looked for the declared phrase and could not see the better
sentence**, so it read three correct cards as disagreements. It had never been
asked: no prediction in the record had ever had an asked distance as its
**largest** contributor until those three rows. A checker agrees with
everything until the day it is asked the question it cannot answer.

It now asks `language` for the same phrase the composer would use, rather than
keeping a second copy — **a checker that reimplements what it checks agrees
with itself.** Two regression tests pin both directions, because a checker
relaxed until it stops complaining is worse than the finding it silenced.

### 4.3 And a remembered number

`test_a_factor_set_query_still_returns_its_own_rows` held `("fs1", 48),
("fs2", 56)` and went red because 16 rows landed in fs2 — the record grew,
which is not a defect. Rewritten to compute both counts from the record and to
assert the property that actually matters: **the factor sets partition**, every
one returns its own standing rows, and none returns zero. **This is the fifth
test of that shape corrected in two days**, after STEP 4's four.

### 4.4 And one test that worked exactly as designed

`test_the_page_has_no_build_step` spells out every file in `web/` so that
"adding a file is a decision somebody makes on purpose — a minified bundle or a
vendored framework would land here and have to be argued for." Vendoring the
fonts landed there and had to be argued for. **The ruling is the argument**, and
it is now written into the test beside `"fonts"`.

## 5. Four things the browser found, three of them mine

**The browser tests are where this session was worst and got best.**

### 5.1 I ran the wrong interpreter, and the gate said nothing

Every full run in this session up to the fourth used the **system Python**
rather than the project's `.venv`. Playwright is not installed there, so all 31
browser tests skipped themselves, **pytest exited 0**, and I reported a green
suite over a run in which the entire rendering half — including four browser
tests I had just written — had never executed.

`requirements-dev.txt` says "skipped if unavailable", and that is right for a
contributor with no browsers. **It is wrong for the gate.** `verify.py` already
has machinery for exactly this — quick mode records a skipped tier so that "not
running a tier is a thing the output has to SAY rather than a silence" — and it
only covered absence by *flag*, never absence by *accident*.

`verify.py` step 1 now checks `find_spec("playwright")` and records the browser
tier as skipped when it cannot run, which routes into the same INCOMPLETE
verdict. **Absence by accident is now treated exactly like absence by
decision.**

### 5.2 Four of my own tests were skipping, not passing

Once they ran, all four skipped: *"no cards on this slate"* on a slate with six.
`show all` does not reveal hidden markup — its handler sets a flag and calls
`renderWeek()`, which **re-fetches and rebuilds the grid**. My helper clicked
and read the DOM in the same breath, catching the page after
`host.innerHTML = ''` and before anything was appended.

**A helper that reports an empty page as an empty slate turns every test built
on it into a test of nothing** — and it fails as a *skip*, which is the quiet
way. It now waits on the post-condition: everything is shown exactly when the
control offering to show it has nothing left to offer.

### 5.3 The hero would not say which pick it was showing

Every grid card carries `data-id`; the hero, alone on the page, carried
nothing. So *"is this pick on the page?"* — the exact question ruling 2's grid
fix exists to answer — **could not be asked about the largest pick on it.**
`renderHero` now sets it, and clears it when it hides.

### 5.4 The sign-in screen 401'd on its own font

`auth.path_is_open` allowed `.css`, `.ico` and `.svg` under `/static/` and not
`.woff2`. The login page loads the stylesheet, the stylesheet asks for the
font, and the font came back **401** — so the sign-in screen drew in a
different face from the app behind it and logged a console error on every
visit. The browser smoke test found it within an hour of the fonts landing.

`.woff2` is now open, on the argument already written there one step further:
**it reveals less than the stylesheet does.** `manrope-latin.woff2` is
byte-identical to the file Google serves anyone who asks, and its SHA-256 is
written down in this repository. The list stays an **extension** allowlist and
not a directory one — `/static/app.js` and `/static/index.html` are still
closed, asserted in the same test that asserts the widening.
